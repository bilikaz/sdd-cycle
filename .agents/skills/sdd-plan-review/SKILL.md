# sdd-plan-review

Read [the plan-review protocol](../../../docs/instructions/implementation/step-plan-review.md).
Follow [review independence](../../../docs/instructions/implementation/cycle.md#independent-reviews):
if this session authored the plan, delegate the whole lead role to a fresh context.
If unavailable, report the limitation instead of reviewing your own plan.
Run one round per authorized invocation.

1. Resolve task and required draft inputs under sdd.plan-review.17. Select the round and exact paths
   under Outputs.
2. Create or reuse assignments under Preparation; specialists own and refresh their source guides.
3. Dispatch applicable fresh specialists with the full sdd.plan-review.11 payload.
   Apply its recovery rules; unavailable capability still leaves a final incomplete-coverage report.
4. Follow the full sdd.plan-review.13 verification and coverage checks, including shared concerns and
   reported limits. Request missing evidence from the responsible reviewer.
5. Freeze current findings before previous verdicts under sdd.plan-review.14. Produce reports from the
   [shared template](../../../docs/instructions/implementation/templates/report.md), following its COMMENTS.
6. Return the final path, summary, coverage status and cleanliness under
   [sdd.cycle.5](../../../docs/instructions/implementation/cycle.md#review-cleanliness).

Follow sdd.plan-review.18: write only assigned preparation/reports and the lead's register entries.
Never edit the plan, ledger, implementation or progress, dispose findings, request settlement, commit or push.
Missing independent coverage is never clean; do not impersonate specialists.
